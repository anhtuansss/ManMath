## ĐÃ ĐẠT

- **HARDCODED-SECRET:** Không thấy khóa/token có vẻ thật trong các file được Git theo dõi. Biến nhạy cảm lấy từ environment; `.env` bị ignore.
- **SQL-INJECTION:** Không thấy raw SQL hoặc Prisma unsafe raw-query. Các truy vấn dùng Prisma API có parameter binding.
- **XSS:** Điểm `dangerouslySetInnerHTML` duy nhất dùng output KaTeX với `trust: false`; văn bản thường được React escape.
- **IDOR / BROKEN-ACCESS-CONTROL:** Các route dữ liệu cá nhân dùng `authMiddleware`; các thao tác practice lọc đồng thời theo `id` và `userId`.
- **MASS-ASSIGNMENT / INSECURE-DESERIALIZATION:** Controller kiểm tra shape/type trước khi dịch vụ xử lý; không thấy `eval`, `vm`, `js-yaml`, hay object-spread L1 vào ORM create/update.
- **SSRF / PATH-TRAVERSAL / COMMAND-INJECTION:** Không thấy request URL hoặc đường dẫn từ HTTP input đi tới network/filesystem/shell. Các `spawn` chỉ thuộc script kiểm thử và dùng executable/args nội bộ, không qua shell.
- **CSRF:** Xác thực dùng Authorization Bearer header, không dùng cookie session; rủi ro CSRF cổ điển không áp dụng cho các endpoint đã xác thực.
- **JWT-NONE-ALGORITHM:** `jsonwebtoken` v9 được dùng với secret HMAC; payload được kiểm tra sau verify. Không thấy decode không xác thực hay `none` algorithm.
- **BRUTE-FORCE / MISSING-RATE-LIMIT / RACE-CONDITION:** Endpoint nộp bài có limiter theo user/IP, idempotency key, unique constraint, và transaction; practice session dùng ownership checks và optimistic revision/concurrency checks.
- **UNRESTRICTED-FILE-UPLOAD / WEAK-PASSWORD-HASHING / VERBOSE-ERROR-DEBUG-MODE:** Không có upload hay password-login flow. Lỗi server trả message chung; stack trace chỉ được log phía server.
- **SLOPSQUATTING:** Import package khớp dependency khai báo/Node built-ins; không thấy package có tên đáng ngờ.

## Kiểm tra dependency

Không thể hoàn tất `npm audit`: môi trường không thể kết nối registry, và lần thử truy cập advisory service bên ngoài bị chặn vì sẽ gửi metadata dependency của repository. Vì vậy, **OUTDATED-DEPENDENCY chưa thể kết luận bằng dữ liệu CVE hiện tại**. `package-lock.json` hiện có, nên hãy chạy `npm audit --omit=dev` cục bộ hoặc trong CI có quyền mạng trước phát hành.

## Bước tiếp theo

1. Đặt CORS allowlist cho staging/dev nếu các môi trường đó có dữ liệu hoặc tài khoản thật.
2. Chạy `npm audit --omit=dev` trong `backend/` và `frontend/` ở môi trường được phép truy cập npm registry.
3. Re-scan sau khi đổi cấu hình CORS.
